# S1.1 Finding: scripted download of monthly A&E CSVs

Date: 7 October 2026. Spike against live NHS England statistics pages from a Windows host.

## Verdict

Scripted download works with `curl` and `httpx` for both HTML year pages and the monthly CSV
files. A descriptive User-Agent is polite but not required for these URLs today. Fallback remains
`nhs-stats fetch --file` if a challenge appears later.

## URL pattern

1. Landing page (index of financial-year pages):
   `https://www.england.nhs.uk/statistics/statistical-work-areas/ae-waiting-times-and-activity/`
2. Year page (lists monthly XLS/CSV and commentaries):
   `.../ae-attendances-and-emergency-admissions-{YYYY}-{YY}/`
   where `{YYYY}-{YY}` is the financial year (April–March), e.g. `2025-26`, `2026-27`.
3. Monthly CSV: under
   `https://www.england.nhs.uk/statistics/wp-content/uploads/sites/2/{upload_year}/{upload_month}/`
   with opaque suffixes. Filenames are not stable month-to-month; examples observed:

| Reporting month | Link text / file pattern | Example URL suffix |
|---|---|---|
| March 2026 (revised 14.05.26) | `Monthly-AE-March-2026-revised-*.csv` | `.../2026/05/Monthly-AE-March-2026-revised-flkg42.csv` |
| February 2026 | `February-2026-CSV-*.csv` | `.../2026/03/February-2026-CSV-Dl8t54.csv` |
| August 2026 | `August-2026-CSV-*.csv` | `.../2026/09/August-2026-CSV-De2k3n.csv` |

Revised releases keep a new file (and often replace the link text with "revised \<date\>"). There is
no predictable hash-free filename; discovery must scrape the year page (or be supplied via `--url`
/ `--file`).

Direct CSV response (March 2026 revised): HTTP 200, `Content-Type: application/octet-stream`,
about 29 KB, `Access-Control-Allow-Origin: *`, CloudFront cache hit. Last-Modified and ETag present.

## Client behaviour

| Client | Landing / year HTML | Direct CSV |
|---|---|---|
| `curl` with project User-Agent | 200 | 200 |
| `curl` with default User-Agent | 200 | 200 |
| `httpx` (`follow_redirects=True`, project UA) | 200 | 200 |
| Earlier agent note: bare `curl` got HTTP 202 CloudFront challenge | Not reproduced on this host/date | n/a |

Recommended User-Agent (already close to `nhs_stats.bronze.USER_AGENT`):
`nhs-stats/0.1 (+https://github.com/hashadar/nhs-open-stats; open data pipeline)`.

## Fallback

If HTML or CSV requests return 202/403 or a bot interstitial: download the CSV manually from the
year page and run `nhs-stats fetch --month YYYY-MM --file path/to.csv` (optionally `--status revised`).

## Layout notes (feeds S1.2)

Confirmed on the March 2026 revised CSV (29 053 bytes, 200 data rows):

- Headers match the package column map after normalising case/spacing; last column is
  `Other emergency admissions` (not the longer “(i.e not via A&E)” wording).
- Provider period labels are `MSitAE-MARCH-2026`.
- The national total is a row with `Period`, `Org Code` and `Org name` all equal to `TOTAL`
  (not a blank org code named ENGLAND).
- Org codes include 3-character trusts and longer UTC/practice codes (up to 6 characters in
  this file); the silver contract pattern is `^[A-Z0-9]{3,6}$`.

## Out of scope here

Automatic year-page scraping and choosing the latest revision per month (S1.3).
